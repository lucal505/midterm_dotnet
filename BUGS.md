Fill it in yourself, in your own words. There is no required number: what counts is that they are real.

| Which rule from ASSIGNMENT.md is violated (R1–R8) | Where the problem was in the starter (file, approximate line) | How you discovered it (test, reading, AI) | What you changed |
|---|---|---|---|
| **R7**: bookings that only touch must not count as overlapping | `Services/BookingService.cs`, line 28: `existing.StartUtc <= endUtc && startUtc <= existing.EndUtc` | Reading the code (AI-assisted). A 10:00–12:00 booking followed by 12:00–13:00 gets a 409 even though they only touch. | Use strict comparisons: `existing.StartUtc < endUtc && startUtc < existing.EndUtc` (put this in a domain method such as `Booking.Overlaps(start, end)`). |
| **R7 / R8**: only **active** bookings conflict; a cancelled booking frees its interval | `Services/BookingService.cs`, lines 26–29: the loop checks every booking for the room, whatever its `Status` | Reading the code (AI-assisted). Cancel a booking, then book the same slot again: you still get 409. | Only check bookings where `Status == BookingStatus.Active` (in the repository query or the domain check). |
| **R8**: cancelling an already cancelled booking must give 409 | `Services/BookingService.cs`, lines 56–60: `Cancel` always sets `Cancelled` | Reading the code (AI-assisted). Cancelling the same booking twice returns 204 both times. | Add `Booking.Cancel()` returning `Result`. It returns a conflict error (409) if the booking is already `Cancelled`; otherwise it sets the status. |
| **R5**: a booking cannot start in the past; "now" must come from `TimeProvider` | `Services/BookingService.cs`, `Create` (lines 8–30): no past-start check. `Program.cs`: `TimeProvider` is never registered. | Reading the code (AI-assisted). A booking starting in 2020 is accepted with 201. | Register `TimeProvider.System` in `Program.cs`, inject it into the create-booking handler, and return 400 if `startUtc < timeProvider.GetUtcNow()`. Don't use `DateTime.UtcNow`. |
| **R6**: maximum duration is 4 hours (exactly 4h is allowed) | `Services/BookingService.cs`, `Create` (lines 8–30): duration is never checked | Reading the code (AI-assisted). A 10-hour booking is accepted. | Return 400 if `endUtc - startUtc > TimeSpan.FromHours(4)` (use `>`, not `>=`, so exactly 4h passes). |
| **API contract**: all errors must be `ProblemDetails` (`application/problem+json`) | `Program.cs`, line 16, and `Middleware/ExceptionMiddleware.cs`: only `BusinessException` becomes a ProblemDetails response | Reading the code (AI-assisted). Errors from the framework itself (malformed JSON body, `GET /api/rooms/abc`) come back as 400/404 with an empty body, not problem+json. | Add `builder.Services.AddProblemDetails()` plus `app.UseExceptionHandler()` / `app.UseStatusCodePages()`, and map `Error` → `Results.Problem(...)` in the endpoints. |
| **R7** (concurrency, minor) | `Services/BookingService.cs`, lines 26–43: the overlap check and the `Add` are not done as one atomic step | Reading the code (AI-assisted). Two requests at the same moment for the same slot can both pass the check and both get saved. | Do the check and the insert in one unit of work / transaction (with EF Core + SQLite). If you do nothing about it, write that down as a known limitation. |
